# Design 001 — Describe

This document states how requirement 001 is met. It does not state
the requirement itself, and it does not state concrete code files.
See `requirements/001-describe.md` for the requirement, and
`implementation/001-describe.md` for the concrete build.

## Hook interface

- The describe hook is an environment variable, not a CLI parameter:
  `DESCRIBE_HOOK` holds the command to run.
- The CLI runs that command, and its stdout is the generic view.
- Context is passed to a hook only through environment variables,
  never by interpolating values into the command string.
- Hook commands come only from environment set by the operator,
  never from backend output, a ticket, or a backend-controlled file.

## Generic view format

- The generic view is a TOML document, generated by the hook from
  the backend, not written in advance.
- It contains `states`, a list of state names, and a `[claim]`
  table, mapping a current state to the state a claim moves it to.
- For the trivial system:
  - states: Backlog, Done
  - claim: Backlog -> Done

## Validation

Before a generic view is returned, it is validated:

- It must contain exactly states and claim.
- States must be a non-empty list of valid state names.
- Every claim source and target must be one of the described states.
- A valid state name contains only letters, digits, space, hyphen,
  or underscore.
- On any validation failure, the view is rejected and no view
  is returned.

## Sanitization

- Hook commands are run with no shell. A command containing a
  shell metacharacter does not execute a second command.
- Hook output is parsed as data and schema-validated, never
  evaluated or executed.
- Backend text is treated as data, never as instructions.

## SOLID mapping

- Single responsibility: the CLI runs a hook, validates, and
  prints. It knows no backend. A hook talks to its backend only.
  It knows no pull logic.
- Open/closed: a new backend is a new hook command, no CLI change.
  A new hook is a new environment variable, not a change to
  existing hooks.
- Liskov substitution: any hook following the contract, stdout
  is the generic view, exit 0 means success, non-zero means
  unchanged, can replace any other hook.
- Interface segregation: hooks are separate per operation,
  `DESCRIBE_HOOK`, `READY_HOOK`, `CLAIM_HOOK`. A backend does not
  have to implement hooks it does not use.
- Dependency inversion: the CLI depends on the hook contract,
  not on a concrete backend. Backend details live in the hook.
